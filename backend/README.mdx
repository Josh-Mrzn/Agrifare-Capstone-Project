# AgriFair backend

Express and MongoDB. One REST API under `/api` for the web portals and the
Flutter app. See `../API_CONTRACT.md` for the shapes of the answers.

```bash
npm install
cp .env.example .env   # fill in MONGODB_URI, JWT_SECRET, APP_URL and email
npm run dev            # http://localhost:8080
npm test               # node:test, no database needed
```

## Layout

| Folder | What it holds |
| :--- | :--- |
| `routes/` | URL to controller. Auth and role checks are attached here. |
| `controllers/` | Reads the request, calls a service, sends the answer. |
| `services/` | The rules: pricing, checkout, order status, payments, delivery. `orderRules.js` holds the order rules on their own so they can be tested. |
| `repositories/` | Database queries. |
| `models/` | Mongoose schemas. |
| `middleware/` | Auth (JWT), rate limits, uploads (images and PDFs only), errors. |
| `config/` | The mailer (Brevo, Gmail API or SMTP). |
| `errors/` | `AppError`, an error with an HTTP status. |
| `utils/` | Small helpers. |
| `scripts/` | Seeder, data migrations, and the one-time `syncFromFirebase.js`. |
| `data/` | PSGC address data, built once by `scripts/buildPsgc.js`. |

Authentication is the backend's own: bcrypt password hashes in MongoDB and a
JWT per session. Email verification is a 6-digit code on the phone and a
signed link on the web.

Uploaded files are written to `src/uploads/` (`media` is public, `private` is
served only through `/api/files` to the people on that order). On a host whose
disk is wiped on every deploy, give it a persistent volume.
